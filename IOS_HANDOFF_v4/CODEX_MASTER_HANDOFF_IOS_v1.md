# 2. Как анализировать чат

Чат содержит:

- требования пользователя;
- принятые решения;
- отвергнутые варианты;
- временные идеи;
- ответы ассистента, часть которых позднее была исправлена.

Не считай каждое предложение ассистента утверждённым требованием.

Создай файл:

`docs/decisions/CHAT_DECISION_LEDGER.md`

Для каждого значимого решения укажи:

| ID | Тема | Решение | Статус | Основание |
|---|---|---|---|---|
| DEC-001 | Основная платформа | Google Sheets + Apps Script | Принято | Пользователь остановился на этом варианте |
| DEC-002 | Отдельное приложение | Не входит в текущий этап | Отложено | Пользователь отказался от перехода |
| DEC-003 | Автоторговля | Не входит в базовый релиз | Отложено | Требуется отдельный RFC/ADR |
| DEC-004 | Связь счетов | Только Account ID | Принято | Ошибки названий уже сломали расчеты |
| DEC-005 | Decision Engine | Единственный источник действий | Принято | Master Specification + Correction Memo |

Допустимые статусы:

- Принято.
- Отвергнуто.
- Отложено.
- Заменено более поздним решением.
- Требует подтверждения.
- Информационный контекст.

При конфликте:

1. более позднее явное решение пользователя имеет приоритет;
2. `ARCHITECTURE_CORRECTION_MEMO_v1.md` имеет приоритет над противоречащим разделом Master Specification v3.0;
3. неизвестное не додумывать;
4. необратимое изменение остановить до ответа пользователя.

# 5. Неприкосновенные правила

## Код и файлы

- Не удалять `.gs`.
- Не удалять `.js` до полного сравнения.
- Не выполнять `clasp push --force` без backup.
- Не менять одновременно локальную и браузерную версии кода.
- Не редактировать крупные модули непосредственно в Apps Script editor.
- Не создавать параллельные реализации существующих модулей.
- Один публичный entry point — одна реализация.
- Один модуль — одна ответственность.

## Данные

- Не очищать рабочие листы без резервной копии.
- Не удалять исторические инструменты и сделки.
- Не считать пользовательские листы источниками бизнес-логики.
- Не связывать счета по русскому названию.
- Не использовать технический кэш как источник истины.
- Не записывать тестовые значения в production-данные без отдельного тестового режима.

## Инвестиционная логика

- Только Decision Engine создаёт действие.
- Ratings не являются рекомендациями.
- При недостатке данных покупка запрещена.
- Нулевая сумма и нулевые лоты не создают рекомендацию.
- Пустой или технический тикер не публикуется.
- Более консервативное решение имеет приоритет.
- Резерв имеет приоритет, если он ниже минимального уровня.

## Безопасность

- Не читать и не выводить токены.
- Не показывать значения Script Properties.
- Не коммитить `.clasprc.json`, OAuth client secrets, `.env` и credentials.
- Не расширять публичный доступ к Apps Script без решения пользователя.
- Перед критическим изменением создавать backup и план отката.

# 12. Этап CODEX-04 — Справочник и Investment Universe

## Справочник

Хранит все известные:

- акции;
- облигации;
- фонды.

Не удаляет историю и не создаёт рекомендации.

## Universe

Содержит инструменты, подходящие стратегии неквалифицированного инвестора.

Разделить:

1. Известен системе.
2. Стратегически доступен.
3. Можно купить сейчас.

Выходной, ночь, праздник и закрытая сессия не исключают инструмент из Universe.

## Universe Diff

Каждое изменение записывать как событие:

- старый статус;
- новый статус;
- причина;
- дата;
- источник;
- идентификатор инструмента.

Decision Engine использует Universe, а не полный Справочник.

# 15. Этап CODEX-07 — базовый Reserve Engine

## Формула

```text
Резерв =
свободные деньги
+
стоимость позиций с ролью «Резерв»
```

## Настройки

- целевой резерв;
- минимальный резерв;
- фонд денежного рынка;
- общий или отдельный резерв;
- возможность использования излишка.

## Расчёт

```text
дефицит = цель - фактический резерв
стоимость лота = цена × размер лота
лоты = floor(min(дефицит, доступные деньги) / стоимость лота)
```

Если лоты равны нулю:

- сделку не создавать;
- показать понятное объяснение.

Reserve Engine создаёт данные/кандидата, но итоговое действие создаёт Decision Engine.

# 19. Первое действие после получения чата и архива

Не начинай кодирование.

Сначала:

1. распакуй архив в отдельную папку;
2. прочитай перечисленные входные документы;
3. создай `CHAT_DECISION_LEDGER.md`;
4. создай список содержимого архива;
5. проверь наличие рабочей папки проекта;
6. выполни только PRE-00;
7. покажи пользователю:
   - что найдено;
   - чего не хватает;
   - какие действия безопасны;
   - какие требуют разрешения;
   - готова ли среда к CODEX-00.

Остановись после отчёта PRE-00.
