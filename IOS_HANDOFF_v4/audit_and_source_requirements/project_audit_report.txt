3. КРИТИЧЕСКИЕ ПРОБЛЕМЫ ДАННЫХ
============================================================

3.1. Ошибка связи счетов и стратегий

В листе “Счета” есть счет:
- Пассивный

В листе “Стратегии счетов” указано:
- Пасивный

Также в “Стратегии счетов” ID счета пустой.

Последствия:
- связи могут не находиться;
- Portfolio Health может считать не те счета;
- общие KPI могут быть неверны;
- рекомендации по счетам могут строиться некорректно.

Что сделать:
- все связи строить только по ID счета;
- русское название использовать только для отображения;
- “Стратегии счетов” не должны быть источником ID вручную: ID должен подтягиваться из листа “Счета”.

3.2. Здоровье портфеля не видит позиции

В листе “Портфель” есть позиции:
- TMON на счете “На тату”: 320.5 RUB
- TPAY на счете “Пассивный”: 10147.0 RUB
- итого по позициям: 10467.5 RUB

Но лист “Здоровье портфеля” показывает:
- стоимость бумаг: 0
- свободные деньги: 84.85
- итого: 84.85
- позиций: 0

Это критическая ошибка ядра расчетов.

Вероятная причина:
- ошибка связи счета и стратегии;
- фильтр активных/включенных счетов;
- расчет общего портфеля берет не тот набор счетов;
- PortfolioHealth работает по счетам/стратегиям через названия, а не ID.

Что сделать:
- сначала исправить accountId linkage;
- затем пересчитать Portfolio Health;
- общий портфель должен учитывать только счета, где “Включать в общий портфель = Да”, но отдельные счета должны быть доступны в отдельном разрезе.

3.3. Оценки дают ложный сигнал покупки

Лист “Оценки”:
- 1895 строк;
- 1859 инструментов имеют решение “Покупать по плану”;
- 1859 инструментов имеют одинаковую оценку 73.

Лист “Рейтинг компаний”:
- 331 строка;
- 316 инструментов имеют оценку 73;
- 316 инструментов имеют решение “Покупать по плану”.

Причины оценки сейчас выглядят так:
- тип инструмента определен;
- отрасль заполнена;
- эмитент заполнен;
- цена есть;
- лотность известна;
- биржа указана.

Это не инвестиционная оценка. Это оценка полноты справочных данных.

Что сделать:
- разделить “полнота данных” и “инвестиционная привлекательность”;
- классификационные признаки не должны давать решение “Покупать”;
- если нет фундаментальных данных, статус должен быть “Недостаточно данных”;
- “Покупать по плану” разрешать только после реальной оценки бизнеса/облигации.

3.4. Советник показывает технические и бессмысленные рекомендации

В “Советник” есть строки:

- не показывать рекомендации на 0 рублей;
- групповые рекомендации отделить от конкретных инструментов;
- для групповых рекомендаций использовать “Тип инструмента: Акции/Облигации/Фонды”, а не тикер.

3.5. План сделок пустой

Лист “План сделок” не содержит строк, хотя Советник уже формирует рекомендации.

Что сделать:

- План сделок должен содержать только конкретные действия с инструментом, ценой, лотом, количеством и суммой;
- групповые отклонения хранить отдельно или помечать как “Групповая рекомендация”.

4. АУДИТ APPS SCRIPT
============================================================

4.1. Конфликт .gs и .js

В папке apps-script одновременно присутствуют .gs и .js файлы с одинаковыми именами.
Например:
- Accounts.gs и Accounts.js
- Advisor.gs и Advisor.js
- BatchSync.gs и BatchSync.js
- Schema.gs и Schema.js
и т.д.

Для многих пар содержимое отличается.
Например:
- Advisor.gs отличается от Advisor.js
- BatchSync.gs отличается от BatchSync.js
- Schema.gs отличается от Schema.js

В .claspignore есть:
**/*.js
.clasp.json
spec_unpack/**

Но ранее clasp push выдавал “Conflicting files found”.

Что сделать:
- Codex должен сначала создать резервную копию;
- сравнить .gs и .js;
- определить источник истины;
- привести проект к одному формату;
- добиться успешных команд clasp status / pull / push / run.

4.2. Дублирующиеся глобальные функции

Найдены дубли функций:
- TI_AutoMaintenanceSync в AutoMaintenance.gs и BatchSync.gs
- TI_MaintenanceSync в AutoMaintenance.gs и BatchSync.gs
- TI_AutoRefreshFastData в AutoMaintenance.gs и DataCache.gs

В Apps Script это может приводить к неочевидному поведению: одна функция переопределяет другую.

Что сделать:
- оставить единственную реализацию каждой публичной функции;
- вспомогательные функции перенести внутрь соответствующих модулей;
- публичные функции меню должны быть тонкими wrapper-функциями.

4.3. Версии модулей не синхронизированы

Core.gs указывает версию 1.1.0.
Многие новые модули имеют версии 2.0.0 / 2.3.0.

Что сделать:
- ввести единый Project Version;
- различать версию проекта и версию отдельного модуля;
- на Главной показывать версию проекта, а не случайную версию модуля.

4.4. Производительность Apps Script

6. СПРАВОЧНИК И ИНВЕСТИЦИОННАЯ ВСЕЛЕННАЯ
============================================================

Текущий Справочник содержит 1895 инструментов:
- 260 акций;
- 1564 облигации;
- 71 фонд.

Целевая инвестиционная вселенная сейчас ограничена тремя типами:
- акции;
- облигации;
- фонды.

Но Справочник пока не доказывает, что все инструменты доступны неквалифицированному инвестору.

Что сделать:
- добавить поле “Доступен неквалифицированному инвестору”;
- добавить поле “Стратегически доступен”;
- добавить поле “Торгуется сейчас”;
- добавить поле “Можно купить сейчас”;
- добавить “Причина временной недоступности”;
- добавить “Причина исключения”.

Важно:
Не исключать инструмент из Инвестиционной вселенной только потому, что сегодня выходной, праздник, ночь или закрытая сессия.

Разделить три уровня:
1. Известен системе — находится в Справочнике.
2. Подходит стратегии — находится в Инвестиционной вселенной.
3. Можно купить сейчас — доступен для Плана сделок.

Не удалять инструменты из Справочника автоматически.
Если инструмент исчез из API или стал неактивен, он получает статус, но остается в истории.

7. РЕЗЕРВ И ФОНД ДЕНЕЖНОГО РЫНКА
============================================================

Сейчас резерв в стратегии считается как свободные деньги.
Это уже не соответствует обновленной стратегии.

Новое правило:
Резерв = свободные деньги + стоимость инструментов с функцией “Резерв”.

Основной инструмент резерва:
- фонд денежного рынка, выбранный пользователем.

Что добавить:
- в стратегию: основной инструмент резерва;
- в справочник/вселенную: “Инструмент резерва = Да”;
- в советник: расчет, сколько лотов фонда денежного рынка купить;
- в план сделок: конкретную строку покупки фонда денежного рынка.

Формула:
недостающая сумма резерва / цена / размер лота = количество лотов, округление вниз.

Если денег меньше одного лота:
показать сообщение, что резерв ниже цели, но суммы недостаточно для минимальной покупки.

8. КУПОННАЯ ЛЕСТНИЦА
============================================================

Новая инвестиционная цель:
облигационная часть должна давать регулярный ежемесячный денежный поток.

Нужно добавить:
- анализ месяцев выплаты купонов;
- распределение купонов по месяцам;
- целевой купонный поток по месяцам;
- отклонение от цели;
- месяцы, которые не закрыты;
- рекомендации облигаций, которые закрывают недостающие месяцы.

Добавить лист:
Купонный календарь.

Поля:
- Месяц;
- Ожидаемый купон;
- Целевой купон;
- Отклонение;
- Уже закрыт;
- Облигации, которые платят в этом месяце;
- Требуется докупить;
- Рекомендованные кандидаты.

Важно:
Купонный месяц не должен быть важнее риска.
Приоритет выбора облигаций:
1. надежность;
2. соответствие стратегии;
3. доходность;
4. дюрация;
5. ликвидность;
6. отсутствие плохих условий;
7. вклад в купонную лестницу.

Нельзя покупать слабую облигацию только ради нужного месяца.

============================================================
13. DEFINITION OF DONE ДЛЯ БЛИЖАЙШЕЙ ИТЕРАЦИИ
============================================================

Итерация считается завершенной, если:
- clasp push не конфликтует из-за .gs/.js;
- нет дублирующихся публичных функций;
- “Стратегии счетов” связываются через accountId;
- Portfolio Health показывает позиции из листа “Портфель”;
- Советник не показывает “00” и “0.00 RUB”;
- План сделок не содержит пустых строк;
- Рейтинг компаний не рекомендует покупку без данных;
- даты отображаются нормально;
- пользователь не видит технические ID;
- работает “Быстро обновить портфель”;
- работает “Полная синхронизация данных”;
- работает “Пересчитать рекомендации” без API;
- сформирован план внедрения Инвестиционной вселенной, Universe Diff, резерва через фонд денежного рынка и купонной лестницы.
