# IOS Architecture Correction Memo v1

## Назначение

Документ фиксирует известные противоречия Master Specification v3.0, которые Codex не должен трактовать самостоятельно.

До выпуска Master Specification v4 этот memo имеет приоритет при конфликте документов.

---

# 1. Главный источник требований

Master Specification остаётся главным источником требований.

Mission Control, Figma Atlas, Roadmap и Google Sheets являются представлениями и не заменяют спецификацию.

---

# 2. Канонический поток

```text
Providers
→ Raw Data
→ Справочник
→ Инвестиционная вселенная
→ Факты
→ Признаки
→ Контекст/знания
→ Специализированные оценки
→ Decision Engine
→ Советник / План сделок / Главная
```

Пользовательские листы не выполняют бизнес-логику и не обращаются к API.

---

# 3. Decision Engine

Только Decision Engine имеет право формировать действие:

- Купить;
- Докупить;
- Держать;
- Сократить;
- Продать;
- Восстановить резерв;
- Купить для купонной лестницы;
- Недостаточно данных.

Bond Engine, Company Rating, Portfolio Engine, Reserve Engine и Coupon Ladder формируют оценки, ограничения и кандидатов, но не публикуют самостоятельную рекомендацию.

Advisor объясняет решение.

Trade Plan преобразует валидное решение в исполнимую строку.

---

# 4. Приоритет факторов

Канонический порядок:

1. Ограничения стратегии.
2. Критические риски.
3. Достаточность данных.
4. Минимальный резерв.
5. Структура портфеля.
6. Качество инструмента.
7. Купонная лестница.
8. Market Regime.

Более консервативное решение имеет приоритет.

---

# 5. Knowledge Engine

Запрещён цикл:

`Knowledge Engine ↔ Bond Engine / Company Rating`.

Канонически:

```text
Facts + Features + Market context
→ Knowledge Engine
→ Bond Engine / Company Rating / Portfolio Engine
→ Ratings
→ Decision Engine
```

Knowledge Engine не использует итоговые оценки этих же модулей как вход в рамках одного расчётного прохода.

Исторические результаты могут использоваться только как отдельный lagged snapshot с явной датой.

---

# 6. Reserve Engine

Reserve Engine не зависит от готовых решений Decision Engine.

Канонические входы:

- Strategy;
- Accounts;
- Portfolio;
- Cash;
- Market Regime;
- Reserve instrument configuration.

Выход:

- фактический резерв;
- минимальный резерв;
- целевой резерв;
- дефицит/излишек;
- допустимый бюджет;
- кандидат восстановления.

Decision Engine принимает итоговое действие.

---

# 7. Portfolio Engine и Portfolio Health

Разделить ответственности:

## Portfolio Structure Engine

Считает:

- стоимость;
- доли;
- отклонения;
- концентрацию;
- структуру по счетам;
- структуру по классам активов.

Не зависит от решений.

## Portfolio Health Aggregator

Использует:

- структуру портфеля;
- качество инструментов;
- резерв;
- ликвидность;
- диверсификацию;
- риск.

Portfolio Health не создаёт действие покупки или продажи.

---

# 8. Счета и стратегии

- Единственный ключ связи — Account ID.
- Название счёта используется только для отображения.
- «Стратегии» — источник параметров стратегии.
- «Стратегии счетов» — связь Account ID ↔ Strategy ID и утверждённые overrides.
- Не дублировать стратегические доли без необходимости.
- Счёт можно исключить из общего портфеля, сохранив индивидуальный анализ.

---

# 9. Справочник и Investment Universe

Справочник хранит все известные инструменты и историю.

Investment Universe хранит стратегически допустимые инструменты.

Отдельно хранить:

- стратегическую доступность;
- торговлю сейчас;
- возможность покупки сейчас.

Закрытая сессия, ночь, праздник и выходной не исключают инструмент из Universe.

---

# 10. Интерфейс

Пользовательский интерфейс полностью русский.

Английские пользовательские названия из документа 28 заменить:

- Investment Universe → Инвестиционная вселенная;
- Portfolio Health → Здоровье портфеля;
- Bond Engine → Анализ облигаций;
- Company Rating → Рейтинг компаний;
- Data Cache → Техническое хранилище данных или скрытый служебный лист.

Внутренние имена модулей могут оставаться английскими.

Не входит в текущий базовый релиз.

Разработка допускается только после:

- отдельного RFC/ADR;
- подтверждённого rollback и контроля риска.
