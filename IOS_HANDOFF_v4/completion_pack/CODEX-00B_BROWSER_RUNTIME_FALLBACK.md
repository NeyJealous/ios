# CODEX-00B — Резервный запуск через Chrome / браузер

## Назначение

Этот этап используется только тогда, когда после выполнения CODEX-00 не удалось настроить вызов Apps Script из терминала через `clasp run-function`, `scripts.run` или MCP.

Цель — не остановить разработку: Codex продолжает запускать безопасные функции через браузерный интерфейс Google Sheets и Apps Script, а результаты сохраняются в журнале и на техническом листе.

CODEX-00B не отменяет поиск причины терминального запуска. Он создаёт временный рабочий канал.

---

# 1. Когда разрешено переходить к CODEX-00B

Переход допускается, если:

- CODEX-PRE-00 завершён;
- рабочая станция настроена;
- `clasp pull/push` либо доступ к редактору Apps Script подтверждены;
- причина отказа машинного запуска классифицирована;
- пользователь явно разрешил browser fallback;
- сохранена резервная копия проекта и таблицы.

Не использовать CODEX-00B как способ обойти ошибку кода.

---

# 2. Возможности browser fallback

Codex может:

- открыть связанную Google Sheets;
- проверить активный Google-аккаунт;
- открыть редактор Apps Script;
- выбрать и запустить top-level функцию;
- передать пользователю окно подтверждения OAuth;
- открыть раздел «Выполнения»;
- прочитать статус, длительность и ошибку;
- проверить результат на техническом листе «Диагностика»;
- проверить пользовательские листы после выполнения;
- сохранить отчёт и скриншоты.

Browser fallback не считается надёжным способом:

- массового тестирования тысяч строк;
- доказательства нулевого количества API-вызовов без инструментирования;
- CI;
- полностью автоматического регрессионного тестирования;
- точного воспроизведения сложных последовательностей без журнала.

---

# 3. Требования безопасности

- Использовать отдельный Chrome-профиль для разработки IOS.
- В профиле не открывать банковские сайты, личную почту и посторонние сервисы.
- Разрешать браузерный доступ только к:
  - `docs.google.com`;
  - `script.google.com`;
  - `accounts.google.com`.
- Не показывать Codex токен T-Invest, OAuth client secret и Script Properties.
- Не копировать credentials в чат, код, Git или листы.
- Любое окно разрешений подтверждает пользователь.
- Не включать публичный или анонимный доступ к Apps Script.

---

# 4. Подготовка диагностических entry points

Все браузерно запускаемые функции должны быть top-level wrapper-функциями.

Минимальный набор:

```javascript
function TI_RemoteHealthCheck() {
  const result = TI.Diagnostics.remoteHealthCheck();
  TI.Diagnostics.persistRunResult_("REMOTE_HEALTH", result);
  console.log(JSON.stringify(result));
  return result;
}

function TI_RunSmokeTests() {
  const result = TI.SmokeTests.runAll();
  TI.Diagnostics.persistRunResult_("SMOKE_TESTS", result);
  console.log(JSON.stringify(result));
  return result;
}

function TI_RunQuickSyncDiagnostic() {
  const result = TI.BatchSync.runDiagnostic_("QUICK");
  TI.Diagnostics.persistRunResult_("QUICK_SYNC", result);
  console.log(JSON.stringify(result));
  return result;
}

function TI_RunRecalcDiagnostic() {
  const result = TI.BatchSync.runDiagnostic_("RECALC");
  TI.Diagnostics.persistRunResult_("RECALC", result);
  console.log(JSON.stringify(result));
  return result;
}
```

Имена адаптировать к фактической архитектуре.

Wrapper-функции:

- не используют active cell;
- не открывают UI;
- не требуют event object;
- используют явный Spreadsheet ID;
- возвращают только JSON-safe значения;
- пишут тот же результат в журнал.

---

# 5. Технический лист «Диагностика»

Создать или проверить скрытый технический лист:

`Диагностика`

Минимальные поля:

- Run ID;
- Дата и время;
- Функция;
- Режим;
- Статус;
- Версия проекта;
- Длительность;
- Количество обработанных строк;
- Количество API-запросов;
- Количество предупреждений;
- Количество ошибок;
- Код ошибки;
- Понятное описание;
- Рекомендуемое действие.

Запись выполняется пакетно.

Пользовательская Главная не показывает stack trace или JSON.

---

# 6. Пошаговый браузерный запуск

1. Открыть отдельный Chrome-профиль IOS.
2. Проверить, что вход выполнен под владельцем Apps Script.
3. Открыть рабочую Google Sheets.
4. Сверить название таблицы и последние шесть символов Spreadsheet ID.
5. Открыть `Расширения → Apps Script`.
6. Сверить последние шесть символов Script ID.
7. Выбрать `TI_RemoteHealthCheck`.
8. Нажать «Выполнить».
9. При появлении OAuth:
   - остановиться;
   - передать управление пользователю;
   - пользователь проверяет список разрешений и подтверждает.
10. Открыть «Выполнения».
11. Проверить:
    - правильную функцию;
    - время;
    - статус;
    - длительность;
    - отсутствие необработанной ошибки.
12. Вернуться в таблицу.
13. Открыть технический лист «Диагностика».
14. Найти Run ID текущего запуска.
15. Сохранить фактический результат в отчёт.

---

# 7. Проверка результата

Browser-тест считается подтверждённым только при наличии трёх доказательств:

1. Статус выполнения в Apps Script.
2. Запись с Run ID в «Диагностика».
3. Ожидаемое изменение или отсутствие изменения в целевом листе.

Для Recalc дополнительно:

- wrapper считает обращения через единый HTTP/provider adapter;
- в диагностике `API-запросы = 0`;
- проверяется отсутствие обновления timestamp внешних источников.

---

# 8. Ограничение изменения кода через браузер

Предпочтительный поток остаётся:

```text
Codex → локальный Git → review diff → clasp push → браузерный запуск
```

Не редактировать большие модули непосредственно в браузерном редакторе Apps Script.

В браузере допускается:

- первичная авторизация;
- запуск функций;
- просмотр Executions;
- просмотр логов;
- мелкое аварийное изменение только после backup и с последующим переносом в Git.

Обязательно указать:

- классификацию ошибки;
- какой Chrome-профиль использован;
- последние 6 символов Script ID и Spreadsheet ID;
- какие функции реально запускались;
- Run ID;
- статус и длительность;
- какие листы проверены;
- какие действия требовали пользователя;
- ограничения текущего канала;
- план возвращения к API/MCP.

Не включать секреты.

---

# 10. Definition of Done

CODEX-00B завершён, если:

- `TI_RemoteHealthCheck` запущен через Apps Script UI;
- выполнение имеет статус «Завершено»;
- результат записан в «Диагностика»;
- рабочая таблица подтверждена;
- Codex может повторить запуск по инструкции;
- создан отчёт;
- терминальная проблема остаётся отдельной зарегистрированной задачей.

После CODEX-00B допускается продолжить CODEX-01—07.

Для окончательного инженерного релиза требуется одно из двух:

1. автоматический канал `scripts.run` / `clasp run-function` / MCP;
2. утверждённый пользователем ручной browser-runbook с полным журналом обязательных тестов.

Первый вариант является целевым.
