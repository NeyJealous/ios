# Investment Operating System (IOS)

# Master Specification v3.0

# 15.5 --- Reserve Engine

**Статус:** Каноническая спецификация управления резервом

## Назначение

Reserve Engine отвечает за управление резервом ликвидности и определяет,
когда свободные денежные средства должны быть сохранены, а когда могут
быть направлены на инвестиции.

Главная цель --- обеспечить постоянную готовность к покупке качественных
активов и исключить длительное хранение капитала без доходности.

------------------------------------------------------------------------

# Основные принципы

1.  Резерв является частью инвестиционной стратегии.
2.  Резерв не считается «мертвыми деньгами».
3.  Основной инструмент хранения резерва --- фонд денежного рынка.
4.  Размер резерва определяется стратегией каждого счета.
5.  Решения по резерву должны быть объяснимы.

------------------------------------------------------------------------

# Источник параметров

Reserve Engine получает настройки из:

-   Стратегии;
-   Профиля счета;
-   Portfolio Engine;
-   Market Regime;
-   Decision Engine.

Запрещено хранить параметры резерва в нескольких местах.

------------------------------------------------------------------------

# Структура резерва

Для каждого счета рассчитываются:

-   целевой резерв;
-   минимальный резерв;
-   фактический резерв;
-   доступный резерв;
-   отклонение;
-   процент выполнения.

Дополнительно рассчитывается общий резерв по всем счетам.

------------------------------------------------------------------------

# Основной инструмент

По умолчанию резерв хранится в выбранном пользователем фонде денежного
рынка.

Параметры фонда:

-   тикер;
-   FIGI (только внутреннее использование);
-   размер лота;
-   текущая цена;
-   доступность;
-   ликвидность.

Пользователь видит только русское название и тикер.

------------------------------------------------------------------------

# Алгоритм восстановления

Если фактический резерв ниже минимального:

1.  Decision Engine получает сигнал.
2.  Новые покупки могут быть ограничены в соответствии со стратегией.
3.  Рассчитывается необходимая сумма восстановления.
4.  Рассчитывается количество лотов фонда.
5.  Формируется объяснимая рекомендация.

------------------------------------------------------------------------

# Алгоритм использования

Если:

-   резерв превышает целевой уровень;
-   стратегия допускает использование;
-   рыночный режим благоприятный;
-   индекс возможностей высокий;

часть резерва может быть использована для покупки активов.

Использование резерва никогда не должно нарушать минимальный уровень.

------------------------------------------------------------------------

# Работа с несколькими счетами

Поддерживаются сценарии:

-   общий резерв;
-   отдельный резерв для каждого счета;
-   выделенный резервный счет;
-   исключение отдельных счетов из расчета общего резерва.

Связь осуществляется только через Account ID.

------------------------------------------------------------------------

# Выходные данные

Reserve Engine формирует:

-   статус резерва;
-   сумму восстановления;
-   количество лотов;
-   рекомендации по покупке фонда денежного рынка;
-   данные для Decision Engine;
-   данные для Portfolio Health.

------------------------------------------------------------------------

# Definition of Done

Reserve Engine считается завершенным, если:

-   резерв рассчитывается автоматически;
-   поддерживаются разные стратегии счетов;
-   количество лотов рассчитывается автоматически;
-   рекомендации объяснимы;
-   параметры стратегии являются единственным источником настройки.
