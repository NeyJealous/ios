# Investment Operating System (IOS)

# Master Specification v3.0

# 09 --- Apps Script Architecture

**Статус:** Каноническая архитектура серверной части IOS.

## Цель

Определить правила построения Apps Script, распределение ответственности
между `.gs` файлами и требования к производительности.

------------------------------------------------------------------------

# Общие принципы

Каждый `.gs` файл представляет самостоятельный модуль.

Каждый модуль обязан:

-   иметь одну ответственность;
-   иметь публичный API;
-   не содержать дублирования логики;
-   использовать существующие источники истины;
-   не обращаться к пользовательским листам как к источнику
    бизнес-логики.

------------------------------------------------------------------------

Analytics → Business

Обратные зависимости запрещены.

------------------------------------------------------------------------

# Правила производительности

Обязательно:

-   getValues()
-   setValues()
-   batch update
-   batch read
-   CacheService
-   PropertiesService
-   LockService
-   Map/Object
-   инкрементальная синхронизация

Запрещено:

-   getRange() внутри циклов;
-   setValue() внутри циклов;
-   appendRow() для массовых операций;
-   очистка листов без необходимости;
-   повторное чтение одного диапазона.

------------------------------------------------------------------------

# Правила API

Перед каждым обращением:

1.  Проверить CacheService.
2.  Проверить timestamp.
3.  Проверить необходимость обновления.
4.  Выполнить пакетный запрос.

------------------------------------------------------------------------

# Ошибки

Все ошибки:

-   журналируются;
-   классифицируются;
-   отображаются понятным сообщением.

Технические сообщения пользователю запрещены.

------------------------------------------------------------------------

# Требования к новым модулям

Каждый новый модуль обязан иметь:

-   описание;
-   владельца;
-   публичные функции;
-   входные данные;
-   выходные данные;
-   зависимости;
-   тестовый сценарий;
-   раздел в Master Specification.

------------------------------------------------------------------------

# Definition of Done

Новый модуль считается завершенным если:

-   не нарушает Конституцию;
-   проходит Code Review;
-   проходит проверку субагентов;
-   документирован;
-   не ухудшает производительность;
-   не создает новый источник истины.
