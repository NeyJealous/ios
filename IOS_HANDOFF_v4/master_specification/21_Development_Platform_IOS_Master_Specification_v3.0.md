# Investment Operating System (IOS)

# Master Specification v3.0

# 21 --- Development Platform

**Статус:** Каноническая спецификация среды разработки

## Назначение

Development Platform определяет единые правила разработки, тестирования,
документирования и сопровождения Investment Operating System.

Этот документ обязателен для всех разработчиков, AI-агентов и
автоматизированных инструментов.

------------------------------------------------------------------------

# Основные компоненты

-   Google Apps Script --- основная платформа исполнения.
-   Google Sheets --- пользовательский интерфейс.
-   Git --- контроль версий.
-   clasp --- синхронизация проекта.
-   Codex --- основной AI-разработчик.
-   MCP --- безопасный доступ AI к проекту.
-   Master Specification --- главный источник требований.

# Роли AI

## Codex

Отвечает за:

-   разработку кода;
-   рефакторинг;
-   исправление ошибок;
-   генерацию тестов;
-   обновление документации.

## MCP

Предоставляет безопасный доступ к:

-   Apps Script;
-   Google Sheets;
-   журналам;
-   диагностике.

Без прямого редактирования через браузер.

## Субагенты

Специализированные помощники:

-   Architecture Reviewer;
-   Apps Script Reviewer;
-   Performance Auditor;
-   Investment Logic Reviewer;
-   Bond Specialist;
-   Company Rating Reviewer;
-   Google Sheets Reviewer;
-   Documentation Reviewer;
-   UX Reviewer;
-   Test Generator.

Каждый субагент отвечает только за свою область.

------------------------------------------------------------------------

# Жизненный цикл задачи

1.  Требование появляется в Master Specification.
2.  При необходимости создаётся RFC.
3.  После утверждения создаётся ADR.
4.  Codex реализует изменение.
5.  Субагенты проводят проверку.
6.  Выполняются тесты.
7.  Обновляется документация.
8.  Изменение включается в релиз.

------------------------------------------------------------------------

# Правила разработки

Любое изменение обязано:

-   соблюдать Конституцию проекта;
-   иметь источник требований;
-   не создавать новый источник истины;
-   быть документировано;
-   сопровождаться тестами.

------------------------------------------------------------------------

# Code Review

Проверяются:

-   архитектура;
-   производительность;
-   инвестиционная логика;
-   UX;
-   документация;
-   соответствие Master Specification.

------------------------------------------------------------------------

# Definition of Done

Задача считается завершённой, если:

-   код работает;
-   тесты пройдены;
-   документация обновлена;
-   архитектура не нарушена;
-   субагенты не выявили критических замечаний;
-   Master Specification актуальна.
