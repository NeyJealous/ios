# Investment Operating System (IOS)

# Master Specification v3.0

# 02 --- Constitution

Статус: Обязательный документ проекта

## Назначение

Конституция определяет фундаментальные правила разработки IOS. Ни один
модуль, лист, функция или изменение не должны противоречить этим
правилам.

------------------------------------------------------------------------

# 1. Архитектурные принципы

1.  Каждый тип данных имеет единственный источник истины.
2.  Пользовательские листы никогда не являются ядром расчетов.
3.  Бизнес-логика отделена от отображения.
4.  Каждый модуль отвечает только за одну область ответственности.
5.  Любая новая функция должна упрощать систему либо не ухудшать её
    архитектуру.

------------------------------------------------------------------------

# 2. Источники истины

-   Сделки --- история операций.
-   Портфель --- текущее состояние.
-   Счета --- перечень счетов.
-   Стратегии --- параметры стратегии.
-   Стратегии счетов --- связь счета со стратегией.
-   Справочник --- полный каталог инструментов.
-   Инвестиционная вселенная --- инструменты, участвующие в анализе.
-   Факты --- нормализованные данные.
-   Признаки --- производные характеристики.
-   Оценки --- скоринг.
-   Решения --- итог Decision Engine.

Главная, Советник и План сделок являются только представлением данных.

------------------------------------------------------------------------

# 3. Пользовательский интерфейс

Обязательно:

-   русский язык;
-   понятные названия;
-   объяснимые рекомендации.

Запрещено отображать:

-   FIGI;
-   UID;
-   Rule_ID;
-   Strategy_ID;
-   Account_ID;
-   внутренние JSON;
-   технические статусы.

------------------------------------------------------------------------

# 4. Производительность

Обязательно использовать:

-   getValues();
-   setValues();
-   batch update;
-   batch read;
-   Map/Object;
-   LockService;
-   CacheService;
-   инкрементальную синхронизацию.

Запрещено:

-   getRange() в циклах;
-   setValue() в циклах;
-   appendRow() для больших объемов;
-   полная очистка листов без необходимости;
-   API-запрос по каждой строке.

------------------------------------------------------------------------

# 5. Синхронизация

Поддерживаются только три режима:

1.  Быстрая синхронизация.
2.  Полная синхронизация.
3.  Пересчет рекомендаций без API.

Любой новый режим должен быть утвержден отдельным ADR.

------------------------------------------------------------------------

# 6. Инвестиционная логика

Любая рекомендация должна быть:

-   объяснима;
-   воспроизводима;
-   основана на данных.

Запрещено рекомендовать покупку при недостатке данных.

Bond Engine обязан учитывать: - доходность; - дюрацию; - кредитный
риск; - ликвидность; - амортизацию; - оферты; - купонную лестницу.

------------------------------------------------------------------------

# 7. Инвестиционная вселенная

Инструмент не исключается только потому, что рынок закрыт.

Разделяются понятия:

-   Стратегически доступен.
-   Торгуется сейчас.
-   Можно купить сейчас.

Все изменения фиксируются в Universe Diff.

------------------------------------------------------------------------

# 8. Документация

Документация имеет приоритет над кодом.

Каждое архитектурное изменение:

1.  Master Specification.
2.  RFC/ADR.
3.  Реализация.
4.  Code Review.

------------------------------------------------------------------------

# 9. Code Review

Каждое изменение проверяется на:

-   соответствие Конституции;
-   производительность;
-   отсутствие дублирования;
-   соблюдение источников истины;
-   корректность инвестиционной логики;
-   соответствие UX.

------------------------------------------------------------------------

# 10. Основной принцип

Investment Operating System должна оставаться простой, понятной,
модульной и масштабируемой.

Любое изменение, нарушающее Конституцию, считается дефектом архитектуры
независимо от того, работает ли код технически.
