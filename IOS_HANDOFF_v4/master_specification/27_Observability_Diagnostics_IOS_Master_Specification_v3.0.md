# Investment Operating System (IOS)

# Master Specification v3.0

# 27 --- Observability & Diagnostics

**Статус:** Каноническая спецификация наблюдаемости и диагностики

## Назначение

Observability & Diagnostics обеспечивает постоянный контроль состояния
Investment Operating System, позволяет быстро выявлять проблемы,
объяснять причины ошибок и измерять производительность всех ключевых
компонентов.

------------------------------------------------------------------------

# Цели

-   обнаруживать проблемы до того, как их заметит пользователь;
-   ускорить поиск причин ошибок;
-   контролировать качество данных;
-   измерять производительность;
-   предоставлять понятную диагностику.

------------------------------------------------------------------------

# Архитектура

Система состоит из пяти подсистем:

1.  Журнал событий.
2.  Журнал ошибок.
3.  Мониторинг производительности.
4.  Проверка целостности данных.
5.  Панель диагностики.

------------------------------------------------------------------------

# Журнал событий

Для каждого запуска сохраняются:

-   дата и время;
-   режим синхронизации;
-   длительность;
-   обновлённые модули;
-   количество обработанных записей;
-   источник данных;
-   итоговый статус.

------------------------------------------------------------------------

# Журнал ошибок

Для каждой ошибки фиксируются:

-   код ошибки;
-   модуль;
-   этап;
-   описание;
-   рекомендуемое действие;
-   возможность автоматического восстановления.

Пользователь видит только понятное описание.

------------------------------------------------------------------------

# Проверка данных

Контролируется:

-   отсутствие пустых тикеров;
-   отсутствие дубликатов;
-   корректность дат;
-   целостность связей Account ID ↔ Strategy ID;
-   наличие обязательных полей;
-   соответствие источникам истины.

------------------------------------------------------------------------

# Мониторинг производительности

Измеряются:

-   время каждого этапа синхронизации;
-   число API-запросов;
-   попадания в кэш;
-   объём чтения и записи листов;
-   время расчёта Decision Engine;
-   время построения Portfolio Health.

------------------------------------------------------------------------

# Диагностика интеграций

Проверяется доступность:

-   T-Invest API;
-   Московской биржи;
-   Банка России;
-   Apps Script;
-   Google Sheets.

------------------------------------------------------------------------

# Панель разработчика

Отображает:

-   состояние синхронизации;
-   время последнего обновления;
-   количество предупреждений;
-   количество ошибок;
-   состояние блокировок;
-   использование лимитов Apps Script.

Эта панель не отображается обычному пользователю.

------------------------------------------------------------------------

# Панель пользователя

Показывает только:

-   «Данные обновлены»;
-   «Источник данных»;
-   «Требуется обновление»;
-   понятные сообщения об ошибках;
-   рекомендации по действиям.

------------------------------------------------------------------------

# Автоматическое восстановление

При обнаружении типовых ошибок система может:

-   повторить запрос;
-   восстановить кэш;
-   повторить синхронизацию;
-   предложить пользователю безопасное действие.

------------------------------------------------------------------------

# Definition of Done

Подсистема считается завершённой, если:

-   контролирует все ключевые процессы;
-   предоставляет понятную диагностику;
-   журналирует ошибки;
-   измеряет производительность;
-   помогает восстановлению без потери данных.
