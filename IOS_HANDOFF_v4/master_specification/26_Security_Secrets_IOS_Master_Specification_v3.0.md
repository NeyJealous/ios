# Investment Operating System (IOS)

# Master Specification v3.0

# 26 --- Security & Secrets

**Статус:** Каноническая спецификация безопасности

## Назначение

Документ определяет требования к защите данных, хранению секретов,
управлению доступом и безопасной эксплуатации Investment Operating
System.

Безопасность рассматривается как часть архитектуры, а не как
дополнительная функция.

------------------------------------------------------------------------

# Основные принципы

1.  Никогда не хранить секреты в исходном коде.
2.  Минимизировать доступ к чувствительным данным.
3.  Все критические действия должны журналироваться.
4.  Пользователь полностью контролирует свои токены и настройки.
5.  Любое изменение прав доступа должно быть осознанным и
    документированным.

------------------------------------------------------------------------

# Категории данных

## Публичные

-   рыночные данные;
-   структура листов;
-   документация.

## Пользовательские

-   настройки стратегий;
-   параметры счетов;
-   пользовательские фильтры.

## Конфиденциальные

-   токен T-Invest;
-   идентификаторы сервисов;
-   ключи интеграций;
-   служебные параметры авторизации.

------------------------------------------------------------------------

# Хранение секретов

Разрешено:

-   PropertiesService;
-   защищённые настройки Apps Script.

Запрещено:

-   хранить токены в Google Sheets;
-   хранить секреты в коде;
-   публиковать секреты в Git;
-   передавать токены через интерфейс.

------------------------------------------------------------------------

# Доступ

Разделяются роли:

-   Пользователь;
-   Разработчик;
-   Codex;
-   MCP;
-   Субагенты.

Каждая роль получает только необходимый минимум прав.

------------------------------------------------------------------------

# Работа Codex

Codex не должен:

-   изменять секреты без явного указания;
-   выводить токены пользователю;
-   сохранять секреты в документации;
-   использовать тестовые значения в рабочем коде.

------------------------------------------------------------------------

# MCP

MCP используется как безопасный слой взаимодействия с:

-   Apps Script;
-   Google Sheets;
-   журналами;
-   диагностикой.

Все изменения должны быть воспроизводимыми.

------------------------------------------------------------------------

# Журнал безопасности

Фиксируются:

-   изменение токена;
-   изменение настроек доступа;
-   изменение структуры проекта;
-   ошибки авторизации;
-   неудачные попытки синхронизации.

------------------------------------------------------------------------

# Резервное копирование

Перед критическими изменениями рекомендуется:

-   сохранить текущую версию Apps Script;
-   создать копию таблицы;
-   сохранить экспорт конфигурации;
-   проверить возможность отката.

------------------------------------------------------------------------

# Definition of Done

Подсистема безопасности считается завершённой, если:

-   секреты не хранятся в коде и таблицах;
-   роли разделены;
-   критические действия журналируются;
-   требования безопасности соблюдаются всеми модулями.
