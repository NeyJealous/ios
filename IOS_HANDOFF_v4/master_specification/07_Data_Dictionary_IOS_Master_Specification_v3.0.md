# Investment Operating System (IOS)

# Master Specification v3.0

# 07 --- Data Dictionary

**Статус:** Каноническая модель данных

## Назначение

Data Dictionary описывает каждую сущность, используемую в системе.

Каждое поле должно иметь одного владельца, один источник истины и
понятное назначение.

------------------------------------------------------------------------

# Общие правила

Для каждого поля определяются:

-   Наименование;
-   Тип данных;
-   Источник;
-   Владелец;
-   Кто использует;
-   Период обновления;
-   Обязательность;
-   Правила валидации.

------------------------------------------------------------------------

# 1. Сущность «Инструмент»

  Поле           Тип       Источник     Используют
  -------------- --------- ------------ -------------------
  FIGI           String    T-Invest     Внутренние модули
  UID            String    T-Invest     Внутренние модули
  Тикер          String    Справочник   Все
  Название       String    Справочник   UI
  Класс актива   Enum      Справочник   Universe
  Валюта         Enum      Справочник   Portfolio
  Лот            Integer   Справочник   Advisor
  Биржа          String    Справочник   UI

FIGI и UID запрещено отображать пользователю.

------------------------------------------------------------------------

# 2. Сущность «Портфель»

  Поле                 Тип      Источник
  -------------------- -------- ------------------
  Account ID           String   Счета
  Тикер                String   Портфель
  Количество           Number   Портфель
  Средняя цена         Number   Портфель
  Рыночная цена        Number   Raw Data
  Рыночная стоимость   Number   Portfolio Engine
  Доходность           Number   Portfolio Engine

------------------------------------------------------------------------

# 3. Сущность «Облигация»

Основные поля:

-   Доходность к погашению (YTM)
-   Дюрация
-   Купон
-   Частота выплат
-   Дата погашения
-   Амортизация
-   Оферта
-   Размер купона
-   Рейтинг
-   Ликвидность
-   Цена
-   НКД
-   Месяцы купонных выплат
-   Подходит для купонной лестницы (Да/Нет)

------------------------------------------------------------------------

# 4. Сущность «Стратегия»

Поля:

-   Название;
-   Целевая доля акций;
-   Целевая доля облигаций;
-   Целевая доля фондов;
-   Целевая доля резерва;
-   Максимальная доля позиции;
-   Максимальная доля сектора;
-   Правила ребалансировки.

Это единственный источник параметров стратегии.

------------------------------------------------------------------------

# 5. Сущность «Профиль счета»

Поля:

-   Account ID;
-   Название счета;
-   Стратегия;
-   Включать в общий портфель;
-   Использовать резерв;
-   Роль;
-   Индивидуальные настройки.

Связь только по Account ID.

------------------------------------------------------------------------

# 6. Сущность «Решение»

Поля:

-   Тип рекомендации;
-   Причина;
-   Приоритет;
-   Сумма;
-   Количество;
-   Количество лотов;
-   Уверенность;
-   Объяснение.

Любое решение должно быть объяснимо.

------------------------------------------------------------------------

# 7. Стандарты именования

-   Русские названия на пользовательских листах.
-   Английские технические имена допускаются только в коде.
-   Не использовать дублирующиеся названия.
-   Один термин --- одно значение.

------------------------------------------------------------------------

# 8. Версионирование

Любое изменение структуры данных требует:

1.  Обновления Data Dictionary.
2.  Проверки совместимости.
3.  Обновления Master Specification.
4.  Обновления кода.
