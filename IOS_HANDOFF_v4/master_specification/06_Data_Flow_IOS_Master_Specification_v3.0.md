# Investment Operating System (IOS)

# Master Specification v3.0

# 06 --- Data Flow

**Статус:** Базовая спецификация потоков данных

## Цель

Определить единственный допустимый жизненный цикл данных внутри
Investment Operating System.

Любые новые модули обязаны использовать этот поток и не могут его
обходить.

------------------------------------------------------------------------

# Принцип

Данные движутся только сверху вниз.

``` text
Внешние API
    ↓
Providers
    ↓
Raw Data
    ↓
Справочник
    ↓
Investment Universe
    ↓
Facts
    ↓
Features
    ↓
Ratings
    ↓
Decision Engine
    ↓
Advisor / Trade Plan / Главная
```

Обратные зависимости запрещены.

------------------------------------------------------------------------

# 1. Providers

Источники данных:

-   T-Invest API;
-   Московская биржа;
-   Банк России;
-   другие официальные источники.

Providers только получают данные.

Никакой инвестиционной логики.

------------------------------------------------------------------------

# 2. Raw Data

Хранятся данные без интерпретации.

Примеры:

-   цены;
-   купоны;
-   дивиденды;
-   ключевая ставка;
-   параметры выпусков;
-   операции.

Источник истины для внешних данных.

------------------------------------------------------------------------

# 3. Справочник

Полный каталог всех известных инструментов.

Не содержит решений.

Не фильтрует бумаги.

------------------------------------------------------------------------

# 4. Investment Universe

Рабочая инвестиционная вселенная.

Фильтрует инструменты по:

-   доступности неквалифицированному инвестору;
-   поддерживаемым классам активов;
-   стратегии;
-   статусу инструмента.

Любое изменение фиксируется в Universe Diff.

------------------------------------------------------------------------

# 5. Facts

Нормализованные объективные данные.

Примеры:

-   YTM;
-   дюрация;
-   цена;
-   купон;
-   рейтинг;
-   P/E;
-   дивидендная доходность.

Факты не содержат оценочных суждений.

------------------------------------------------------------------------

# 6. Features

Производные признаки.

Например:

-   высокая доходность;
-   длинная дюрация;
-   высокий риск;
-   недооценена;
-   подходит для резерва;
-   закрывает купонный месяц.

------------------------------------------------------------------------

# 7. Ratings

Каждый модуль выставляет собственную оценку:

-   Bond Engine;
-   Company Rating;
-   Portfolio Engine;
-   Reserve Engine.

Оценки не являются рекомендациями.

------------------------------------------------------------------------

# 8. Decision Engine

Объединяет оценки.

Формирует объяснимые решения:

-   Купить;
-   Докупить;
-   Держать;
-   Сократить;
-   Продать;
-   Недостаточно данных.

------------------------------------------------------------------------

# 9. Presentation Layer

Состоит из:

-   Главная;
-   Советник;
-   План сделок;
-   Portfolio Health;
-   Отчеты.

Эти листы не выполняют сложных вычислений.

Они только отображают результат Decision Engine.

------------------------------------------------------------------------

# 10. Запрещённые зависимости

Запрещено:

-   Главная → API;
-   Advisor → Providers;
-   Portfolio Health → Raw Data;
-   Trade Plan → самостоятельно рассчитывать стратегию;
-   Business Layer → пользовательские листы.

------------------------------------------------------------------------

# 11. Проверка потока

Любой новый модуль должен ответить на вопросы:

1.  Откуда получает данные?
2.  Кто является источником истины?
3.  Какой слой использует?
4.  Кто использует его результат?
5.  Может ли модуль быть переиспользован?

Если ответы неоднозначны --- архитектура требует пересмотра.
