# Investment Operating System (IOS)

# Master Specification v3.0

# 03 --- Architecture

Статус: Базовая архитектурная спецификация

## Цель

Определить единую архитектуру системы, распределение ответственности
между модулями, поток данных и правила взаимодействия компонентов.

------------------------------------------------------------------------

# 1. Архитектурные слои

    Внешние источники
            │
            ▼
    Провайдеры данных (T-Invest, MOEX, ЦБ)
            │
            ▼
    Данные источников (Raw Data)
            │
            ▼
    Справочник инструментов
            │
            ▼
    Инвестиционная вселенная
            │
            ▼
    Факты
            │
            ▼
    Признаки
            │
            ▼
    Оценки
            │
            ▼
    Decision Engine
            │
            ▼
    Advisor / Trade Plan / Главная

Данные движутся только сверху вниз. Обратные зависимости запрещены.

------------------------------------------------------------------------

# 2. Основные модули

## Data Layer

-   Providers
-   API
-   Raw Data
-   Data Cache

Отвечает только за получение и хранение исходных данных.

## Core Layer

-   Directory
-   Investment Universe
-   Facts
-   Features
-   Ratings
-   Decisions

Ядро всей системы.

## Business Layer

-   Bond Engine
-   Company Rating
-   Portfolio Engine
-   Reserve Engine
-   Coupon Ladder
-   Knowledge Engine
-   Advisor

Реализует инвестиционную стратегию.

## Presentation Layer

-   Главная
-   Советник
-   План сделок
-   Отчеты

Ничего не рассчитывает самостоятельно.

------------------------------------------------------------------------

# 3. Источники истины

  Объект                      Источник
  --------------------------- --------------------------
  История                     Сделки
  Портфель                    Портфель
  Стратегии                   Стратегии
  Связь счетов                Стратегии счетов
  Инструменты                 Справочник
  Анализируемые инструменты   Инвестиционная вселенная
  Рыночные данные             Raw Data
  Итоговые рекомендации       Решения

------------------------------------------------------------------------

# 4. Правила зависимостей

Разрешено:

-   Bond Engine → Facts
-   Company Rating → Facts
-   Decision Engine → Ratings
-   Advisor → Decisions

Запрещено:

-   Главная → API
-   Advisor → API
-   Portfolio Health → визуальные листы
-   Trade Plan → самостоятельно рассчитывать стратегию.

------------------------------------------------------------------------

# 5. Архитектура синхронизации

Поддерживаются только:

1.  Быстрая синхронизация.
2.  Полная синхронизация.
3.  Пересчет рекомендаций.

Каждый режим имеет собственную область ответственности.

------------------------------------------------------------------------

# 6. Архитектура кэша

Уровень 1: CacheService.

Уровень 2: PropertiesService (временные метки, курсоры).

Уровень 3: Листы с кэшированными данными.

Ни один модуль не должен выполнять API-запрос без проверки актуальности
данных.

------------------------------------------------------------------------

# 7. Многосчетная архитектура

Счет связывается со стратегией только по ID.

Каждый счет может: - входить в общий портфель; - иметь собственную
стратегию; - использоваться для хранения резерва; - исключаться из общих
расчетов.

------------------------------------------------------------------------

# 8. Инвестиционная вселенная

Справочник содержит полный каталог.

Инвестиционная вселенная --- только инструменты, подходящие стратегии.

Изменения фиксируются в Universe Diff.

------------------------------------------------------------------------

# 9. Принципы расширения

Любой новый модуль обязан: - иметь одну ответственность; - использовать
существующие источники данных; - не дублировать расчеты; - не создавать
новый источник истины; - быть описан в Master Specification до
реализации.

------------------------------------------------------------------------

# 10. Definition of Architecture Done

Архитектура считается завершенной, если:

-   отсутствуют циклические зависимости;
-   каждый модуль имеет одну ответственность;
-   поток данных однонаправленный;
-   все пользовательские листы являются только представлением;
-   новые функции могут добавляться без изменения существующих слоев.
