# Investment Operating System (IOS)

# Master Specification v3.0

# 19 --- Cache Strategy

**Статус:** Каноническая спецификация стратегии кэширования

## Назначение

Cache Strategy определяет правила хранения, повторного использования и
обновления данных, чтобы минимизировать обращения к внешним API,
ускорить работу системы и исключить превышение лимитов Google Apps
Script.

------------------------------------------------------------------------

# Принципы

1.  Любые данные переиспользуются максимально долго, пока остаются
    актуальными.
2.  Перед каждым API-запросом обязательно проверяется кэш.
3.  У каждого типа данных собственное время жизни (TTL).
4.  Кэш никогда не является источником истины --- только ускорителем
    доступа.
5.  Инвалидация кэша должна быть предсказуемой и документированной.

------------------------------------------------------------------------

# Трёхуровневая архитектура

## Уровень 1 --- Runtime Cache

Используется:

-   CacheService.

Назначение:

-   ускорение повторных вызовов внутри короткого периода;
-   хранение часто используемых результатов;
-   снижение количества одинаковых запросов.

------------------------------------------------------------------------

## Уровень 2 --- Persistent Cache

Используется:

-   PropertiesService.

Хранятся:

-   timestamps;
-   курсоры синхронизации;
-   версии справочника;
-   контрольные суммы;
-   параметры последнего обновления.

------------------------------------------------------------------------

## Уровень 3 --- Data Cache

Используются специальные листы проекта.

Хранятся:

-   результаты тяжелых вычислений;
-   исторические значения;
-   агрегированные данные;
-   данные, получение которых занимает значительное время.

------------------------------------------------------------------------

# Категории данных

Для каждой категории задаются:

-   владелец;
-   источник;
-   TTL;
-   правила обновления.

## Портфель

Обновляется только быстрой или полной синхронизацией.

## Сделки

Инкрементальная загрузка.

История не перезаписывается.

## Справочник

Редко изменяется.

Обновляется только полной синхронизацией.

## Investment Universe

Перестраивается только после изменения Справочника или стратегии.

## Рыночные цены

Обновляются чаще остальных данных.

## Bond Engine

Пересчитывается только при изменении входных данных.

## Company Rating

Использует готовые Facts и Features.

## Portfolio Health

Пересчитывается только при изменении структуры портфеля.

------------------------------------------------------------------------

# Инвалидация

Кэш должен очищаться только при:

-   изменении входных данных;
-   изменении версии алгоритма;
-   полной синхронизации (для соответствующих категорий);
-   явном запросе пользователя.

Полная очистка всего кэша запрещена.

------------------------------------------------------------------------

# Правила использования

Перед любым вычислением:

1.  Проверить Runtime Cache.
2.  Проверить Persistent Cache.
3.  Проверить Data Cache.
4.  Выполнять вычисление только при необходимости.

------------------------------------------------------------------------

# Контроль качества

Любой модуль обязан:

-   фиксировать время последнего обновления;
-   сообщать источник данных;
-   отображать пользователю:
    -   "Данные обновлены";
    -   "Источник";
    -   "Данные устарели" (при необходимости).

Термин "Кэш" в пользовательском интерфейсе не используется.

------------------------------------------------------------------------

# Definition of Done

Cache Strategy считается завершенной, если:

-   реализовано трехуровневое кэширование;
-   каждый тип данных имеет собственный TTL;
-   отсутствуют лишние API-запросы;
-   инвалидация выполняется предсказуемо;
-   стратегия полностью документирована.
