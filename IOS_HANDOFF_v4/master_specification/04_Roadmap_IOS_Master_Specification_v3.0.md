# Investment Operating System (IOS)

# Master Specification v3.0

# 04 --- Roadmap

Статус: План развития проекта

## Назначение

Roadmap определяет порядок разработки IOS. Любой новый модуль
реализуется только после выполнения зависимостей предыдущих этапов.

------------------------------------------------------------------------

# Phase 1 --- Stabilization (Текущий приоритет)

Цель: Создать устойчивую архитектурную основу.

Основные задачи: - стабилизация синхронизации; - Investment Universe; -
Universe Diff; - исправление ядра расчетов; - многосчетная
архитектура; - резерв через фонд денежного рынка; - купонная лестница; -
оптимизация Apps Script; - Master Specification.

Definition of Done: - три режима синхронизации работают; - отсутствуют
ложные рекомендации; - все расчеты используют единое ядро; -
документация актуальна.

------------------------------------------------------------------------

# Phase 2 --- Investment Core

Модули: - Facts; - Features; - Ratings; - Decision Engine; - Bond
Engine; - Company Rating.

Definition of Done: - рекомендации полностью воспроизводимы; - каждый
показатель имеет источник данных; - отсутствуют прямые обращения к API
из аналитических модулей.

------------------------------------------------------------------------

# Phase 3 --- Performance

Основные задачи: - многоуровневый кэш; - batch-операции; - incremental
sync; - оптимизация листов; - устранение повторных чтений.

Метрика: значительное сокращение времени полной синхронизации и
пересчета.

------------------------------------------------------------------------

# Phase 4 --- Knowledge

Развитие Knowledge Engine.

Задачи: - объяснение рекомендаций; - накопление знаний; - улучшение
качества аналитики.

------------------------------------------------------------------------

# Phase 5 --- Portfolio Intelligence

Добавить: - прогнозирование структуры; - анализ концентрации; -
улучшенный Portfolio Health; - расширенный анализ резервов; - сценарный
анализ.

------------------------------------------------------------------------

# Phase 6 --- Execution

One Click Execution.

Подготовить архитектуру безопасного формирования заявок. Автоматическое
исполнение не является обязательной частью текущей версии.

------------------------------------------------------------------------

# Непрерывные процессы

После каждой завершенной задачи обязательно:

1.  Code Review.
2.  Проверка субагентами.
3.  Smoke Test.
4.  Обновление документации.
5.  Обновление Roadmap.
6.  Обновление Project History.

------------------------------------------------------------------------

# Definition of Project Done

Проект считается зрелым, если:

-   архитектура модульна;
-   документация актуальна;
-   отсутствуют дублирующиеся источники истины;
-   пользователь получает объяснимые рекомендации;
-   производительность соответствует установленным требованиям;
-   развитие новых функций не требует переработки существующей
    архитектуры.
