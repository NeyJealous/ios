# Investment Operating System (IOS)

# Master Specification v3.0

# 15.7 --- Ребалансировка

**Статус:** Каноническая спецификация ребалансировки

## Назначение

Ребалансировка поддерживает фактическую структуру портфеля в
соответствии с целевой стратегией при минимальном количестве операций и
минимальных издержках.

------------------------------------------------------------------------

# Основные принципы

1.  Основа --- целевые доли стратегии.
2.  Приоритет отдается докупке, а не продаже.
3.  Продажа выполняется только при наличии веских причин.
4.  Не создавать сделки ради незначительных отклонений.
5.  Любая рекомендация должна быть объяснима.

------------------------------------------------------------------------

# Входные данные

Используются:

-   Стратегии;
-   Профили счетов;
-   Портфель;
-   Reserve Engine;
-   Decision Engine;
-   Market Regime;
-   Portfolio Engine.

------------------------------------------------------------------------

# Расчет целевых долей

Для каждого счета используются доли **только** из выбранной стратегии.

Поддерживаются:

-   индивидуальная стратегия счета;
-   общий портфель;
-   исключение отдельных счетов;
-   разные целевые доли для разных счетов.

Запрещено использовать фиксированные веса в коде.

------------------------------------------------------------------------

# Коридоры отклонений

Для каждого класса активов и позиции определяются:

-   целевая доля;
-   фактическая доля;
-   абсолютное отклонение;
-   относительное отклонение;
-   допустимый диапазон.

Ребалансировка запускается только при выходе за пределы допустимого
диапазона.

------------------------------------------------------------------------

# Приоритет действий

1.  Использовать свободные денежные средства.
2.  Использовать превышение резерва (если разрешено).
3.  Докупить недостающие позиции.
4.  Только затем рассматривать сокращение превышающих позиций.

------------------------------------------------------------------------

# Расчет покупки

Для каждой рекомендации рассчитываются:

-   сумма;
-   количество бумаг;
-   количество лотов;
-   остаток денежных средств;
-   влияние на структуру портфеля.

Рекомендации с суммой 0 или количеством 0 запрещены.

------------------------------------------------------------------------

# Продажа

Продажа допускается только если:

-   существенно превышена целевая доля;
-   изменена стратегия;
-   ухудшилось качество актива;
-   необходима ребалансировка.

Снижение цены само по себе не является причиной продажи.

------------------------------------------------------------------------

# Многосчетная логика

Ребалансировка выполняется:

-   по каждому счету;
-   по объединенному портфелю;
-   с учетом роли каждого счета;
-   с учетом индивидуальных стратегий.

------------------------------------------------------------------------

# Объяснение пользователю

Каждая рекомендация должна содержать:

-   текущее отклонение;
-   целевую долю;
-   причину;
-   ожидаемый эффект после выполнения.

------------------------------------------------------------------------

# Definition of Done

Модуль считается завершенным если:

-   использует только параметры стратегии;
-   поддерживает многосчетную архитектуру;
-   не создает нулевых рекомендаций;
-   рассчитывает количество лотов автоматически;
-   полностью документирован.
