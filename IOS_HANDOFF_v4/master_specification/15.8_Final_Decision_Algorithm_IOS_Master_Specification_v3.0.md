# Investment Operating System (IOS)

# Master Specification v3.0

# 15.8 --- Финальный алгоритм принятия инвестиционных решений

**Статус:** Каноническая спецификация принятия решений

## Назначение

Данный документ определяет полный порядок формирования инвестиционных
рекомендаций.

Никакой модуль не может изменить последовательность принятия решений без
изменения Master Specification.

------------------------------------------------------------------------

# Главный принцип

Каждая рекомендация должна быть:

-   безопасной;
-   воспроизводимой;
-   объяснимой;
-   соответствующей стратегии;
-   проверенной всеми необходимыми модулями.

------------------------------------------------------------------------

# Последовательность работы

``` text
1. Проверка состояния системы
        ↓
2. Проверка синхронизации
        ↓
3. Portfolio Engine
        ↓
4. Market Regime
        ↓
5. Reserve Engine
        ↓
6. Bond Engine
        ↓
7. Company Rating
        ↓
8. Coupon Ladder
        ↓
9. Decision Engine
        ↓
10. Advisor
        ↓
11. План сделок
```

Пропуск этапов запрещён.

------------------------------------------------------------------------

# Этап 1. Проверка данных

До начала анализа система обязана проверить:

-   актуальность синхронизации;
-   корректность кэша;
-   отсутствие ошибок;
-   наличие обязательных данных.

При отсутствии данных анализ прекращается.

------------------------------------------------------------------------

# Этап 2. Анализ портфеля

Определяются:

-   структура;
-   отклонения;
-   здоровье портфеля;
-   концентрация;
-   риски.

------------------------------------------------------------------------

# Этап 3. Анализ рынка

Учитываются:

-   ключевая ставка;
-   инфляция;
-   рыночный режим;
-   индекс возможностей.

------------------------------------------------------------------------

# Этап 4. Проверка резерва

Определяется:

-   достаточно ли резерва;
-   требуется ли восстановление;
-   можно ли использовать часть резерва.

Если стратегия требует восстановления резерва --- новые покупки получают
более низкий приоритет.

------------------------------------------------------------------------

# Этап 5. Анализ инструментов

Для каждого кандидата выполняется:

-   проверка Investment Universe;
-   анализ Bond Engine или Company Rating;
-   проверка Portfolio Engine;
-   проверка ограничений стратегии;
-   проверка концентрации;
-   проверка качества данных.

------------------------------------------------------------------------

# Этап 6. Формирование кандидатов

Для каждого инструмента определяется:

-   Купить;
-   Докупить;
-   Держать;
-   Сократить;
-   Продать;
-   Недостаточно данных.

------------------------------------------------------------------------

# Этап 7. Разрешение конфликтов

Приоритет:

1.  Ограничения стратегии.
2.  Критические риски.
3.  Reserve Engine.
4.  Portfolio Engine.
5.  Bond Engine / Company Rating.
6.  Coupon Ladder.
7.  Market Regime.

Более консервативное решение имеет приоритет.

------------------------------------------------------------------------

# Этап 8. Распределение бюджета

Доступные средства распределяются между рекомендациями с учетом:

-   стратегии;
-   целевых долей;
-   лимитов;
-   количества лотов;
-   приоритета рекомендаций.

------------------------------------------------------------------------

# Этап 9. Формирование рекомендаций

Каждая рекомендация содержит:

-   действие;
-   инструмент;
-   счет;
-   стратегия;
-   сумма;
-   количество;
-   количество лотов;
-   ожидаемый эффект;
-   причины;
-   уровень уверенности.

------------------------------------------------------------------------

# Этап 10. Проверка качества

Перед публикацией выполняются проверки:

-   нет пустых тикеров;
-   нет рекомендаций на 0 рублей;
-   нет рекомендаций с 0 лотов;
-   нет инструментов вне Investment Universe;
-   нет необъяснимых решений.

При обнаружении ошибки рекомендация блокируется.

------------------------------------------------------------------------

# Definition of Done

Алгоритм считается завершенным, если:

-   все этапы документированы;
-   отсутствуют обходные пути;
-   решения воспроизводимы;
-   рекомендации полностью объяснимы;
-   Advisor и План сделок используют только результаты данного
    алгоритма.
