# Investment Operating System (IOS)

# Master Specification v3.0

# 18 --- Synchronization

**Статус:** Каноническая спецификация синхронизации данных

## Назначение

Система синхронизации обеспечивает актуальность данных при минимальном
количестве API-запросов, соблюдении лимитов Apps Script и полной
воспроизводимости результатов.

------------------------------------------------------------------------

# Принципы

1.  API вызывается только при необходимости.
2.  Любые доступные локальные данные используются повторно.
3.  История никогда не загружается полностью без причины.
4.  Все операции выполняются пакетно.
5.  Одновременно может работать только одна синхронизация.

------------------------------------------------------------------------

# Режимы синхронизации

## 1. Быстрая синхронизация

Назначение: ежедневное обновление.

Обновляет: - счета; - портфель; - свободные средства; - цены; -
Главную; - Portfolio Health; - Advisor; - План сделок.

Не обновляет историю сделок и справочник.

------------------------------------------------------------------------

## 2. Полная синхронизация

Обновляет:

-   сделки;
-   операции;
-   справочник;
-   Investment Universe;
-   источники данных;
-   факты;
-   признаки;
-   оценки;
-   решения;
-   купоны;
-   дивиденды.

Запускается вручную или по расписанию.

------------------------------------------------------------------------

## 3. Пересчет рекомендаций

Не обращается к API.

Использует только локальные данные.

Пересчитывает:

-   Portfolio Engine;
-   Bond Engine;
-   Company Rating;
-   Decision Engine;
-   Advisor.

------------------------------------------------------------------------

# Инкрементальная загрузка

История операций обновляется только новыми записями.

Используются:

-   курсор;
-   timestamp;
-   уникальный идентификатор операции.

Дубликаты исключаются.

------------------------------------------------------------------------

# Кэширование

Перед любым API-вызовом:

1.  Проверить CacheService.
2.  Проверить PropertiesService.
3.  Проверить timestamp.
4.  Выполнить запрос только при необходимости.

------------------------------------------------------------------------

# Пакетные операции

Обязательно использовать:

-   getValues();
-   setValues();
-   пакетные запросы API;
-   Map/Object в памяти.

Запрещено:

-   getRange() в циклах;
-   setValue() в циклах;
-   appendRow() для больших объемов.

------------------------------------------------------------------------

# LockService

Любая синхронизация должна получать блокировку.

При невозможности получения:

-   завершить выполнение;
-   записать событие в журнал.

------------------------------------------------------------------------

# Журнал

Для каждого запуска сохраняются:

-   дата;
-   режим;
-   длительность;
-   обновленные модули;
-   количество API-запросов;
-   ошибки;
-   результат.

------------------------------------------------------------------------

# Восстановление

При ошибке:

-   сохранить частично обновленные данные;
-   не очищать листы;
-   предложить повторную синхронизацию;
-   журналировать исключение.

------------------------------------------------------------------------

# Definition of Done

Система синхронизации считается завершенной, если:

-   реализованы три режима;
-   используется инкрементальная загрузка;
-   минимизированы API-запросы;
-   соблюдаются лимиты Apps Script;
-   полностью документирована.
