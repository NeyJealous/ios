# Investment Operating System (IOS)

# Master Specification v3.0

# 20 --- Performance

**Статус:** Каноническая спецификация производительности

## Назначение

Документ определяет требования к скорости работы, масштабируемости и
эффективности Investment Operating System.

Производительность рассматривается как обязательное архитектурное
требование, а не как последующая оптимизация.

------------------------------------------------------------------------

# Цели

-   минимальное время ожидания пользователя;
-   минимальное количество API-запросов;
-   соблюдение лимитов Google Apps Script;
-   возможность масштабирования проекта без деградации скорости.

------------------------------------------------------------------------

# Основные принципы

1.  Любые данные читаются пакетно.
2.  Любые данные записываются пакетно.
3.  Повторные вычисления запрещены, если результат уже доступен.
4.  API используется только после проверки кэша.
5.  Производительность важнее удобства реализации.

------------------------------------------------------------------------

# Требования к Apps Script

Обязательно использовать:

-   getValues();
-   setValues();
-   CacheService;
-   PropertiesService;
-   LockService;
-   Map / Set / Object;
-   пакетную обработку данных.

Запрещено:

-   getRange() внутри циклов;
-   setValue() внутри циклов;
-   appendRow() для массовой записи;
-   многократное чтение одного диапазона;
-   полную очистку листов без необходимости.

------------------------------------------------------------------------

# Целевые показатели

## Быстрая синхронизация

Цель: до 30 секунд для типового портфеля.

## Полная синхронизация

Цель: минимально возможное время за счёт инкрементальной загрузки и
пакетной обработки.

## Пересчёт рекомендаций

Без внешних API.

Цель: несколько секунд даже при большом количестве инструментов.

------------------------------------------------------------------------

# Оптимизация памяти

Все промежуточные вычисления выполняются в памяти.

Рекомендуется:

-   использовать словари (Map);
-   индексировать данные один раз;
-   избегать копирования крупных массивов;
-   очищать временные структуры после использования.

------------------------------------------------------------------------

# Работа с листами

Каждый лист читается один раз за этап обработки.

Каждый лист записывается одной или минимальным количеством операций.

------------------------------------------------------------------------

# Работа с API

Перед каждым запросом:

1.  Проверить кэш.
2.  Проверить timestamp.
3.  Выполнить пакетный запрос.
4.  Обновить кэш.

------------------------------------------------------------------------

# Контроль производительности

Для каждого запуска журналируются:

-   длительность;
-   число API-запросов;
-   объём обработанных данных;
-   число обновлённых строк;
-   количество предупреждений;
-   ошибки.

------------------------------------------------------------------------

# Code Review

Каждый Pull Request проверяется на:

-   отсутствие лишних запросов;
-   отсутствие чтения листов в циклах;
-   отсутствие записи по одной ячейке;
-   корректное использование кэша;
-   соблюдение архитектуры.

------------------------------------------------------------------------

# Definition of Done

Подсистема считается соответствующей требованиям, если:

-   выдерживает целевые показатели;
-   не нарушает лимиты Apps Script;
-   использует пакетную обработку;
-   документирована;
-   проходит проверку производительности.
