# Investment Operating System (IOS)

# Master Specification v3.0

# 24 --- Testing Strategy

**Статус:** Каноническая стратегия тестирования

## Назначение

Документ определяет единый подход к тестированию Investment Operating
System.

Цель --- гарантировать корректность инвестиционной логики, стабильность
архитектуры и отсутствие регрессий после каждого изменения.

------------------------------------------------------------------------

# Основные принципы

1.  Каждое требование должно иметь проверку.
2.  Каждая ошибка должна приводить к появлению нового теста.
3.  Тесты являются частью проекта и поддерживаются наравне с кодом.
4.  AI-разработчики обязаны запускать тесты перед завершением задачи.

------------------------------------------------------------------------

# Уровни тестирования

## Unit

Проверяются отдельные функции:

-   расчёт долей;
-   расчёт лотов;
-   расчёт YTM;
-   Portfolio Health;
-   Decision Engine.

------------------------------------------------------------------------

## Integration

Проверяется взаимодействие модулей:

-   Synchronization → Portfolio;
-   Portfolio → Decision Engine;
-   Bond Engine → Coupon Ladder;
-   Reserve Engine → Advisor.

------------------------------------------------------------------------

## End-to-End

Полный сценарий:

1.  Синхронизация.
2.  Обновление данных.
3.  Пересчёт.
4.  Формирование рекомендаций.
5.  Проверка пользовательских листов.

------------------------------------------------------------------------

# Обязательные сценарии

-   Новый счёт.
-   Новый инструмент.
-   Покупка акций.
-   Покупка облигаций.
-   Восстановление резерва.
-   Купонная лестница.
-   Исключение счёта из общего портфеля.
-   Изменение стратегии счёта.
-   Полная синхронизация.
-   Быстрая синхронизация.
-   Пересчёт без API.

------------------------------------------------------------------------

# Регрессионные проверки

Перед релизом обязательно убедиться, что:

-   рекомендации не изменились без причины;
-   отсутствуют пустые тикеры;
-   отсутствуют рекомендации на 0 ₽;
-   интерфейс полностью на русском языке;
-   технические идентификаторы скрыты.

------------------------------------------------------------------------

# Метрики качества

Контролируются:

-   время синхронизации;
-   число API-запросов;
-   количество предупреждений;
-   число ошибок;
-   покрытие тестами критических модулей.

------------------------------------------------------------------------

# Definition of Done

Функция считается завершённой только после успешного прохождения всех
обязательных тестов.
